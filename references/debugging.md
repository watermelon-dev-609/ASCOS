# 系统化调试模式（Systematic Debugging）— P0

Bug 修复应有独立于新功能开发的流程，避免「看到报错就直接 Patch 症状」。

## 流程
1. **复现问题**：明确触发条件与期望 / 实际行为。
2. **收集证据**：日志、堆栈、请求 / 响应、数据状态、环境信息。
3. **定位根因**：区分症状与根因，找到真正来源，而非表面修复。
4. **最小修复**：只改必要的部分，不夹带无关重构。
5. **补回归测试**：用用例锁定该 Bug，防止复发。
6. **复测**：原问题消失，且受影响路径未引入新回归。

## 注意
- 修复前先理解相关代码（见 `repository-awareness.md`）。
- 评估变更影响（见 `change-impact.md`）后再动手。
- 对应工作流第 10 步：修 Bug 走本流程而非普通「测试」步骤。

## 反模式
- 不看日志直接改代码猜位置。
- 只屏蔽报错、不解决根因。
- 顺手做大范围重构导致新回归。
