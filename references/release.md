# 发布 / 迁移 / 回滚（Release / Migration / Rollback）— P1

企业级软件工程不能停在本地代码，需覆盖上线、迁移与回滚。

## 检查项
- **Schema / 数据迁移方案**：可回滚、评估锁表 / 数据量影响。
- **向后兼容策略**：API / 数据格式是否破坏既有客户端。
- **部署顺序**：依赖启动顺序、配置先于代码等。
- **灰度或分阶段发布**（适用时）。
- **回滚或 Forward Fix 方案**：出问题如何恢复。
- **上线后健康检查与关键指标确认**。

## 原则
- 仅在涉及实际上线 / 部署的任务触发，不要为本地开发强行套用。
- 引入任何基础设施先说明收益与成本（反过度设计）。
- 对应工作流第 15 步。
