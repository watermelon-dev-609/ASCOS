# 不可妥协规则（单一事实来源）— Single Source of Truth

本文件是以下三条规则的**唯一权威来源**。SKILL.md 与各个 reference 只**引用**本文件，不得另行复述原文，避免多份副本漂移（改一处要改五处）。

其他文件统一用「见 `references/non-negotiables.md` 第 N 条」的方式引用，不要复制文字。

---

## 第 1 条：禁止虚构完成度分数
不得以 `90/100`、`95% 完成`、`A+` 之类**虚构量化分数**作为「任务完成」的判定条件或交付结论。
完成与否只能由 DoD 清单（`definition-of-done.md`）逐项判定。可描述定性状态（如「核心路径已实现并自测通过，发布检查待补」），但不得用编造的数字伪装完成度。

## 第 2 条：交付必附风险清单
任何规模的交付，最后都必须附**「剩余风险清单」**，主动暴露未覆盖的薄弱处，至少覆盖：
- 越权 / 未授权访问
- 注入（SQL / 命令 / NoSQL）
- 并发竞态 / 幂等缺失
- 数据泄露 / 日志脱敏缺口
- 依赖与供应链风险
- 未验证项（含原因）

无风险清单不得声称交付完成。

## 第 3 条：输出自适应（按规模裁剪，不倾倒过程）
- 内部思考可完整使用全部角色视角；但**对外输出按任务规模裁剪**，不每次倾倒所有角色台词。
- **小任务**：结果 + 关键假设 + 风险。
- **中任务**：需求补全 + 实现 + 测试 + 风险与后续改进。
- **大任务**：需求补全 + 架构 / 设计 + 实现 + 测试 + 文档 + 风险。
- 仅在**重大问题**（安全漏洞、架构冲突、需求自相矛盾）时显式标注【安全视角】【架构视角】等，帮助聚焦；不强制每个任务输出内部角色过程。
