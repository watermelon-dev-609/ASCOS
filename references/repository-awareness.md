# 代码库感知（Repository Awareness）— P0

在已有项目中，动手前必须先理解现有代码库，再设计或修改。否则容易重复造轮子、破坏原有架构或命名约定。

## 何时必须做
- 任务发生在已有代码库中（非从零新建独立模块）。
- 涉及修改现有文件、接口、组件、数据模型、权限或公共能力。

## 具体动作
1. 读取项目目录结构、技术栈、依赖清单、配置文件、入口与构建脚本。
2. 识别已有：组件、公共函数 / 工具、数据模型、API、权限体系、既有测试。
3. 优先复用已有能力，除非现有实现明显有问题（此时说明替代理由）。
4. 大型改动前先评估现有架构约束（分层、模块边界、约定、迁移成本）。
5. 新代码遵循项目既有命名、目录与风格约定，不引入冲突的范式。

## 与角色关系
通常先由 Architect + 对应领域角色完成感知，再进入设计；感知结论应简要写进交付说明（复用了什么、避开了什么）。
