# PRD — 产品需求文档

## 1. 背景与目标
- 要解决什么问题 / 用户价值
- 成功标准（可衡量）

## 2. 用户与角色
- 目标用户 / 操作者（actors）
- 权限与边界

## 3. 功能范围
- 核心功能（Must）
- 该有但用户没提的（AI 主动补全）
- 明确不做（Out of scope）

## 4. 需求补全记录
- 原始需求（用户原话）
- 隐含需求 / 边界 / 异常 / 安全 / 性能 / 可观测性
- 关键假设（已假设，未确认）

## 5. 验收标准
- 可测试的条件列表

## 6. 风险与开放问题
- 风险
- 需用户确认的业务决策

---
> 文档链路：本 PRD 是需求源 → ADR（关键决策）→ API_SPEC（接口）→ TEST_PLAN（验收与风险）。需求变更时同步更新下游（见 `references/artifact-continuity.md`）。
