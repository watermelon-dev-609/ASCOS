## 二、当前卡点：证据阶梯三級皆不可得，按契约必须停下

`debugging` 的失败状态规则（来自契约表）：L0 红环不可得 → **显式降级**到 L1/L2 继续分析；**仅当连 L2 级证据都没有**才停止并请求环境/产物。

当前逐项核验：

| 级别 | 内容 | 可得性 |
|---|---|---|
| **L0** 红环 | 可复现步骤 + 浏览器 Console 首屏报错全文 + 完整堆栈 | ✗ 我无法访问浏览器与线上环境 |
| **L1** | 服务端 / 网关日志、前端监控（Sentry 等）错误事件、SourceMap 还原、本次发布 diff | ✗ 未提供 |
| **L2** | 基于代码与配置的静态推断（入口文件、构建配置、路由、Nginx/CDN 配置） | ✗ 本轮未被授权读取仓库文件 |

**结论：连 L2 都拿不到 → 停止，请求环境与产物。** 这是契约规定的动作。

为什么不直接猜：白屏至少有 8 类成因（见第四节），且它们的**修复动作完全不在一个层面**（改 Nginx / 改构建配置 / 改代码 / 清缓存）。凭现象猜等于赌，会把止血时间从分钟级拖到小时级，并可能造成第二次故障。

## 三、需要你提供的「最小取证包」（按性价比排序，前 3 项可判定约 80% 的情况）

**1）浏览器侧（最关键，30 秒可得）**
- F12 → Console：首屏**第一条**红色报错的完整文本 + 堆栈
- F12 → Network：按状态码排序，列出所有**非 200** 的请求，特别是 `index.html`、`main.*.js`、`chunk-*.js`、`*.css` 的 Status 与 Response 内容
- F12 → Application：是否注册了 Service Worker

> 拿到后能排除什么：Console 有堆栈 → 指向 H3/H6/H8；Console 干净但资源 404 → 指向 H1/H7；Console 有 "Refused to execute" → 指向 H6。

**2）HTML 与产物侧**
```bash
curl -sI https://<线上域名>/            # 看状态码、Content-Type、缓存头
curl -s  https://<线上域名>/ | head -50  # 看 script/link 的 src 指向哪里
curl -s -o /dev/null -w "%{http_code}\n" https://<线上域名>/<上一条拿到的 js 路径>
```
- 同时贴出构建产物 `dist/index.html` 的内容
- 服务器 / Nginx 的 SPA fallback 配置（`try_files` / `location /`）
- 是否配置了 CSP、资源是否带 `integrity`（SRI）

**3）现象边界（决定影响面与是否回滚）**
- 全站所有路由都白，还是只有子路由白、根路径正常？
- 刷新是否必现？**无痕窗口**是否正常（能区分缓存/SW 与真实产物问题）？
- 全量用户还是部分（按地域 / 浏览器 / 灰度批次）？

**4）本次发布 diff**
```bash
git log --oneline <上一可用版本 tag>..HEAD
git diff <上一可用版本 tag>..HEAD -- package.json package-lock.json <构建配置文件> <路由文件>
```
重点：是否动过 `base`/`publicPath`、路由模式、依赖版本、CI 环境变量、网关/CDN 配置。

**5）服务端与监控**
- 网关 / Nginx access log 与 error log（有无 5xx、404 峰值）
- 前端监控（Sentry 或自有上报）里的 error 事件与 SourceMap 还原结果

## 四、假设清单（⚠️ 全是**假设**，未经证据验证，按经验概率排序，非结论）

| # | 假设 | 典型表现 | 一条动作即可证伪 |
|---|---|---|---|
| H1 | 静态资源 404 / `base`、`publicPath` 或 CDN 前缀变更，或 Nginx `root` 未更新 | Console 无 JS 报错；Network 里 js/css 404；HTML 只剩空 `<div id="root">` | `curl` 那个 js 路径看返回码 |
| H2 | SPA history 模式 fallback 缺失 / 网关路由未同步 | 根路径正常，直接访问子路由返回 404 页 | `curl` 一个子路由看返回码与内容 |
| H3 | 渲染期 JS 运行时异常（框架崩溃卸载 DOM） | Console 有红色堆栈；常见于依赖升级、接口返回结构变化、必填环境变量缺失 | 贴堆栈即可定位 |
| H4 | 环境变量构建期未注入（CI secrets 缺失、前缀写错 `VITE_`/`REACT_APP_`） | API base 为 `undefined`，请求打到相对路径或直接抛错 | 在页面执行 `console.log(import.meta.env)` 或看产物里是否被替换成空串 |
| H5 | CDN / 浏览器缓存或 Service Worker：旧 HTML + 新 chunk 名（或反之） | **无痕窗口正常、普通窗口白屏** | 无痕窗口对比 |
| H6 | CSP 或 SRI（`integrity`）不匹配，脚本被浏览器拦截 | Console 出现 "Refused to execute ... Content Security Policy" | 看 Console 与响应头 |
| H7 | 依赖版本漂移（lockfile 未提交 / CI 装到新 minor） | 本地构建正常，CI 产物白屏 | 对比本地与 CI 的 `lockfile` 与 `npm ls` |
| H8 | 动态 chunk 加载失败（`ChunkLoadError`，灰度节点未同步） | Console 出现 `ChunkLoadError` / `Loading chunk failed` | 贴报错 + 该 chunk 的 curl 结果 |

## 五、止血建议（**需你确认后我才执行**）

1. **首选：回滚到上一个可用版本** —— 对线上全量白屏，这是最快且可逆的止血手段。
   **我不会自行执行**：属于需确认操作。请确认「目标版本号 + 回滚方式（镜像回滚 / 重新部署 / 网关切流）」。
2. **不能回滚时的针对性处置**（须先由证据锁定假设）：
   - H1/H2 → 修正资源路径与 Nginx fallback
   - H5 → SW 版本号 + 缓存失效，资源文件名加 hash，CDN 刷新
   - H6 → 修正 CSP 头或 SRI 哈希
   - H4 → 补齐构建期环境变量后重新构建
3. **明确不要做**：不要在线上直接热改代码而不留版本；不要为了让报错消失而先关掉监控告警。

## 六、根因确定后的执行约定

- **最小修复**：只针对根因，不顺手重构、不顺手升级依赖。
- **回归测试（红→绿）**：先写一条能复现白屏的红测 —— E2E 冒烟：打开首页与 2 个关键路由，断言 `#root` 非空 **且** 无 console error；修复后转绿。
- **补防线**：
  - 构建期校验：产物 `index.html` 引用的资源文件全部存在
  - 发布后自动冒烟：部署完成立即 headless 访问首页并断言已渲染，失败则自动回滚
  - 前端错误监控 + SourceMap 上传（否则下次仍然"看不见"）

## 八、剩余风险清单

1. **根因未定，白屏仍在持续** —— 若为全量白屏，属 P0，每分钟都在产生损失；止血优先级高于定位。
2. **若无前端错误监控**，同类问题下次仍不可见，只能等用户反馈 —— 建议补 Sentry + 发布后自动冒烟。
3. **若 lockfile / 构建配置未纳入版本控制**，本地与 CI 产物会长期不一致，H7 类问题会反复出现。
4. **若未上传或未保留 SourceMap**，即使拿到堆栈也只能定位到压缩后代码，MTT R 显著变长。
5. **回滚本身的风险**：若本次发布同时包含接口或数据结构变更，仅回滚前端会与后端不匹配，需确认前后端是否需同步回滚。
6. **证据缺失带来的二次风险**：凭现象猜测并热修，很可能引入第二个故障。
