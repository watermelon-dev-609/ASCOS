### 3.2 你没说、但登录功能默认必须补齐的边界

按核心信念第 1 条（用户需求默认不完整），以下为主动补全项：

**安全（不可妥协）**
- 密码哈希存储 + 每用户随机盐；不明文、不回显、不进日志
- 登录接口速率限制 + 失败锁定/退避，防暴力破解与账号枚举
- 错误提示统一化（防用户名枚举）
- Cookie：`HttpOnly` + `Secure` + `SameSite`；Session  fixation 防护（登录后轮换 Session ID）
- CSRF 防护（若用 Cookie 会话）
- 登出 = 服务端会话失效，不只是前端清 token
- 所有密钥/盐/签名密钥走环境变量或密钥管理，**我不会向你索要明文口令或密钥**
- 校验：入参长度/格式/字符集限制，防注入

**功能边界**
- 记住我 / 会话有效期与续期策略
- 找回密码与重置流程（是否一期做）
- 首次登录引导、重复登录、并发会话策略
- 受保护路由的未登录跳转与 401/403 语义区分

**可观测性**
- 登录成功/失败埋点与审计日志（不含密码、不含完整 token）
- 失败率告警阈值

**数据**
- 是否已有用户表；若有，迁移方案与存量密码处理
- 唯一性约束、索引、大小写/空格归一化

**测试**
- 单测：密码哈希与校验、会话签发与失效、参数校验
- 集成：登录成功/失败/锁定/登出/未授权访问
- 安全用例：错误密码、枚举、越权访问受保护资源、会话过期

### 3.3 验收标准（DoD 草案，进 `verification` 时逐项判定）

1. 正确凭据可登录，错误凭据被拒，且两次错误返回一致提示
2. 连续失败达到阈值后账号/来源 IP 被限流或锁定
3. 未登录访问受保护资源 → 按约定跳转或返回 401
4. 登出后原会话立即失效（旧会话不可再用）
5. 数据库中不存在明文口令，日志/响应中不含口令与完整令牌
6. 会话 Cookie 属性符合 `HttpOnly`/`Secure`/`SameSite` 要求
7. Build / Test / Lint / Type Check **四者均有真实执行输出**，无一项是口头声称通过
8. 关键路径有自动化测试覆盖，且失败时测试确实变红（红绿循环有证据）

## 4. 阻断项：这些问题需要你拍板（在写第一行代码之前）

编排器硬性要求：**大任务额外必问架构分叉点——数据归属、权限模型、同步 vs 异步、是否多租户**。以下缺失会导致两条完全不同的实现路径，故不自行假设。

**P0（不回答无法开工）**
1. **技术栈与运行形态**：前后端是否分离？后端语言/框架？现有持久化是什么？（决定了是 Session-Cookie 还是 Token 方案）
2. **账号来源**：自建账号密码，还是接入已有身份源（OIDC / OAuth / LDAP / 企业微信）？是否要第三方登录？
3. **权限模型范围**：一期只做「登录态」二态，还是必须带角色/权限点？
4. **是否多租户 / 数据归属**：用户数据归属单组织还是多组织隔离？

**P1（影响范围与工期，可先给默认值）**
5. 找回密码 / 邮箱验证是否本期做？
6. 是否需要 MFA（短信/TOTP）？
7. 是否已有用户表与存量账号需要迁移？
8. 会话有效期、记住我、并发会话策略？
9. 部署与上线窗口，是否需要灰度/回滚方案？

## 6. 安全不可妥协项（进 `architecture` 时按 `references/security.md` 展开）

- 不自研密码学，不自造会话令牌
- 登录相关的每一条外部输入都视为恶意输入，白名单校验
- 失败路径与成功路径同样被测试覆盖（错误提示不得泄漏账号是否存在）
- 密钥、盐、签名密钥只走环境变量/密钥管理；不索要、不落盘、不进版本库
- 上线前强制安全审查 + 发布检查
