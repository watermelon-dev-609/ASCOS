## 2. `requirements` 阶段产出 — 需求补全（事实 / 假设 / 建议 三分）

### 事实（F = 来自用户原话或 Skill 规则，非推断）

- **F1** 用户要求「给这个项目加个登录功能」。
- **F2** 改动发生在**已存在的项目**上 → 必须走 `repository-awareness.md` + `change-impact.md`，优先复用既有设施，评估改这一处会影响哪些地方。

- **F4** 凭据/密钥一律走环境变量，我**不会索要明文口令**。
- **F5** 本次未获得代码库上下文（见 C1）。

### 假设（A = 我替你补全的默认，若与事实不符请直接否掉）

- **A1** 常规「账号 + 密码 + 会话」登录，不是 SSO / OAuth / 短信验证码 / magic link。
- **A2** 需要用户存储；密码必须哈希（argon2id，无则 bcrypt），**绝不存明文**。
- **A3** 登录后需要「保持会话」（Session Cookie 或 Refresh Token），不是每请求重登。
- **A4** 存在「登录后才可见」的页面/接口 → 需要统一鉴权中间件 + 未登录跳转/401。
- **A5** 本期权限只区分「已登录 / 未登录」，**不做 RBAC 角色细分**。
- **A6** 需要：登出使会话立即失效、防暴力破解（限流 / 失败计数 / 锁定）、CSRF 防护（若用 Cookie 会话）。

### 建议（S = 需你点头才落地）

- **S1** 优先复用项目现有 Web 框架的**官方/原生鉴权方案**与既有中间件，**不自研令牌格式**。
- **S2** 反过度设计：**不默认引入 Redis / MQ / 微服务 / K8s**。会话存哪里取决于你的部署形态（见 Q3）；若确需引入，我会写明收益与成本再让你拍板。
- **S3** 密码哈希 argon2id（退而 bcrypt），禁 MD5 / SHA 裸哈希。
- **S4** **默认拒绝**：新增接口默认需鉴权，白名单显式声明（`/login`、静态资源、健康检查、回调）。
- **S5** 登录审计日志：记录 谁 / 何时 / IP / 成功失败；**不记录**密码与完整令牌。
- **S6** 易变技术事实（框架版本、安全默认值）按 `research-freshness.md` 查官方文档后再定，不凭记忆。

## 3. 验收标准（DoD 草案，确认后固化为测试点）

- 正确凭据可登录并跳转；错误凭据**统一提示**，不区分「用户不存在 / 密码错误」（防账号枚举）。
- 未登录访问受保护资源：接口返回 401，页面 302 到登录页，登录后回到原目标地址（**且 returnUrl 需白名单校验，防开放重定向**）。
- 登出后当前会话**立即失效**（服务端侧失效，不只是前端删 Cookie）。
- 密码以哈希落库；明文不出现在日志、响应体、错误信息、URL 中。
- 连续失败 N 次触发限流/锁定；Cookie 会话具备 CSRF 防护，且 `Secure` / `HttpOnly` / `SameSite` 设置正确。
- 测试：单元（密码校验、令牌签发与校验）+ 集成（登录 → 访问受保护接口 → 登出）+ **至少 1 条未登录/越权负向用例**。
- 证据：**Build / Test / Lint / Type Check 四条真实命令输出**，缺一即按 `verification` 判定「未完成」，不得声称通过（root 核心信念 6、契约表 `verification` 失败状态）。

## 4. 待确认清单（阻断项，请逐条回复；或直接说「按你的默认 A1–A6 走」）

> 大任务架构分叉点，root 明确规定：**确认后再进入实现**。

- **Q1 权限模型**：只要「已登录 / 未登录」布尔态，还是本期就要角色权限（RBAC / 多角色）？
  → 这决定中间件与数据模型，后期从布尔改 RBAC 通常需要重构（风险 R6）。
- **Q2 身份来源**：自建账号密码？还是要接第三方（OIDC / 企业微信 / GitHub / Google）？是否需要「记住我」「多端互踢」？
- **Q3 会话形态（同步/存储分叉）**：服务端 Session（Cookie）还是 JWT 无状态？**是否多实例/多副本部署？**
  → 多实例是决定「是否必须引入 Redis 等共享存储」的唯一依据，我不默认引入。
- **Q4 数据归属 / 多租户**：用户表放现有库，还是独立库/独立服务？是否多租户（租户间账号隔离）？注册入口谁负责——开放注册 / 邀请码 / 仅管理员建号？（「忘记密码 / 重置」是否本期做？）
- **Q5 解除阻断 C1（最关键）**：请提供或允许我读取
  1. 技术栈与版本（前端框架、后端框架与版本、语言运行时）；
  2. 目录结构（贴一棵目录树即可）与 `CONTEXT.md`（若有）；
  3. 现有是否已有用户表 / 用户目录 / 鉴权中间件 / 会话方案 / 密码哈希库；
  4. 构建、测试、Lint、类型检查命令。
- **Q6 是否本期上线？** 上线则我会在 `verification` 阶段追加发布检查（`release.md` + `observability.md`），并且**不会替你执行发布动作**。

**关于凭据**：我不需要你的明文口令。只需告知环境变量名（如 `AUTH_SECRET`、`DATABASE_URL`），实现从环境变量读取。
