## 二、requirements：需求补全与验收标准

### 事实（来自用户原话）
- 需求：给订单列表加**分页**和**关键字搜索**。

### 假设（我主动补全的默认值，可直接推翻）
| # | 假设 | 默认值 | 若被推翻的影响 |
|---|---|---|---|
| A1 | 分页形态 | 页码式 `page`（从 1 开始）+ `size`，默认 `page=1, size=20`，`size` 上限 100 | 改游标分页需改接口契约 |
| A2 | 响应结构 | `{ items, total, page, size, totalPages }` | 前端需同步调整 |
| A3 | 搜索范围 | 订单号（精确优先）+ 客户名 / 手机号 / 商品名（模糊） | 决定索引方案 |
| A4 | 匹配方式 | 大小写不敏感，前后模糊（`LIKE '%kw%'`），trim 后最大长度 64 | 前置通配符影响索引命中 |
| A5 | 排序 | `created_at DESC` **且带确定性 tie-breaker `id DESC`** | 无 tie-breaker 会翻页重复/漏数据 |
| A6 | 组合能力 | 关键字 + 分页 + 既有筛选/排序可叠加，语义为 AND | — |
| A7 | 权限 | 先做权限/租户过滤，**再**应用关键字；越权搜索结果一律不返回 | 顺序颠倒会泄露数据 |
| A8 | 参数化 | 一律参数化查询，禁止字符串拼 SQL | 否则 SQL 注入 |
| A9 | 深分页 | 暂不做游标分页；`page` 过大时返回空列表而非报错 | 数据量上涨后需重评 |
| A10 | 前端交互 | 输入防抖 300ms；keyword 变化重置到第 1 页；状态同步到 URL query | — |

### 建议（非必须，收益/成本已标注）
1. **count 与 list 共用同一 WHERE 条件**，否则总数与内容不一致。
2. 大数据量下 `LIKE '%kw%'` 无法命中 B-tree 索引；数据量达百万级再引入全文索引/搜索引擎，**当前不做**（反过度设计）。
3. 手机号既是搜索字段又是敏感数据：**日志脱敏**，搜索关键字不得明文写入访问日志。
4. 前端空态/错误态/加载态三态齐全，翻页与搜索结果区加 `aria-live`。

### 验收标准（可测）
- AC1 无参数调用返回第 1 页 20 条，且 `total` 等于权限范围内订单总数。
- AC2 `page=2&size=20` 与第 1 页**无重复、无遗漏**（用确定性排序保证）。
- AC3 `size=0 / size=101 / page=0 / page=-1 / page=abc` 返回 400 与明确错误信息。
- AC4 `keyword` 命中订单号时精确结果排在最前；命中客户名/手机号/商品名时模糊返回。
- AC5 `keyword` 含 `'`、`%`、`_`、SQL 片段时按字面匹配，不报错、不注入。
- AC6 跨用户搜索：用 A 的 token 搜 B 的订单号，结果为空（越权隔离）。
- AC7 `keyword` 变化后自动回到第 1 页；翻页时 keyword 不丢失。
- AC8 权限范围内 0 条时返回空 `items` + `total=0`，不报错。

### 需确认项（仅列会阻断正确执行的，其余按默认值推进）
1. **兼容性分叉**：不传分页参数时，是「返回全部（兼容老调用方）」还是「一律返回第 1 页」？—— 直接决定是否有破坏性变更。**此项未确认前不落盘改动。**
2. **数据权限边界**：订单隔离维度是「用户」还是「组织/租户」？—— 影响 WHERE 条件与越权测试用例。
3. **搜索字段范围**：只搜订单号，还是含客户名/手机号/商品名？手机号涉及 PII，需确认是否合规可搜。

## 三、implementation：实现方案（seam 级，待代码库上下文确认后落盘）

**分层**：Controller（参数校验/边界）→ Service（权限过滤 + 条件组装）→ Repository（参数化 SQL）。

- Controller 校验：`page` 为 ≥1 整数；`size` ∈ [1,100]；`keyword` trim 后长度 ≤64；非法值统一 400。
- Service：先注入租户/用户过滤条件，再叠加 keyword；排序固定 `ORDER BY created_at DESC, id DESC`。
- Repository（参数化示意）：
  ```sql
  WHERE tenant_id = :tenantId
    AND (:keyword IS NULL OR order_no = :kwExact OR customer_name ILIKE :kwLike OR phone LIKE :kwLike)
  ORDER BY created_at DESC, id DESC
  LIMIT :size OFFSET :offset
  ```
  计数查询共用同一 WHERE（不含 LIMIT/OFFSET）。
- 前端：`{ page, size, keyword }` 单一状态源，防抖 300ms，keyword 变更重置 page，状态写入 URL query 以支持刷新与分享。
- 测试清单：参数边界、翻页不重不漏（AC2）、关键字转义（AC5）、越权（AC6）、空结果（AC8）、原无参调用回归。
