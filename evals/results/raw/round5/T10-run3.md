## 1. 前置澄清（阻塞项，需你回答后我才动代码）

1. **商品字段集**：最小集是 `name / sku / price / currency / status` 吗？是否需要 `description / category_id / images / stock / weight / barcode / tax_rate`？
2. **删除语义**：物理删除还是软删除（`deleted_at`）？软删除是否需要恢复接口与查询默认过滤？
3. **价格与金额类型**：`decimal(18,4)` / 整数分 / 字符串？是否涉及多币种与四舍五入规则？
4. **幂等**：创建接口是否需要 `Idempotency-Key`（防重复提交/网络重试）？
5. **权限**：谁可写？是否需要 RBAC 鉴权 + 租户/店铺维度的数据隔离（多租户场景最容易出问题）？
6. **唯一性约束**：`sku` 全局唯一还是店铺内唯一？冲突返回 409 还是 200 + 错误体？
7. **列表能力**：分页方式（cursor 还是 offset）、需要哪些筛选/排序字段、是否需要模糊搜索？
8. **现有约定**：项目已有的分层（Controller/Service/Repository？或 CQRS？）、DTO 命名、错误响应格式、migration 工具、OpenAPI 生成方式 — 需与之一致，我不另起一套。

### 建议的 API 草案（待与现有约定对齐）

```
POST   /api/v1/products            创建商品
GET    /api/v1/products            列表（分页 / 筛选 / 排序）
GET    /api/v1/products/{id}       详情
PATCH  /api/v1/products/{id}       部分更新（推荐，避免 PUT 的覆盖语义歧义）
DELETE /api/v1/products/{id}       软删除
POST   /api/v1/products/{id}:restore   恢复（仅软删除方案需要）
```

### 错误码草案

| 场景 | 状态码 |
| --- | --- |
| 参数校验失败 | 400 |
| 未登录 / 越权访问他店商品 | 401 / 403 |
| 商品不存在或已被软删除 | 404 |
| `sku` 唯一键冲突 | 409 |
| 价格/库存等业务规则不满足 | 422 |

## 3. 验证清单（verification Skill 执行项）

- **单元测试**：字段校验边界（价格为 0、负数、超长 name）、sku 冲突、软删除后查询不可见
- **集成测试**：真实 DB 跑完整 CRUD 链路，含 migration 回滚
- **契约测试**：请求/响应 schema 与 OpenAPI 一致，破坏性变更会被 CI 拦下
- **并发**：并发创建同 sku 只成功一个；并发更新用乐观锁（`version` 或 `updated_at`）避免丢失更新
- **幂等**：同 `Idempotency-Key` 重复提交只产生一条记录
- **安全**：越权读写（改 id 访问他店商品）必须 403/404；列表接口必须带租户过滤
- **性能基线**：列表接口在 10w 数据量下的 P95，确认索引生效（无全表扫描）
