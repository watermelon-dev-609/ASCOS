## 2. 当前状态：证据不足，按契约显式停下

`debugging` 的失败状态规定：L0 红环不可得时，按证据阶梯**显式降级**到 L1/L2 继续分析；**仅当连 L2 级证据都没有时才停止并请求环境/产物**。

现在就属于这种情况：我手上只有现象「打开就白屏」，没有任何环境、日志或产物信息 —— 连 L2 级证据都拿不到。所以我不给根因结论，先索取最小证据集。**这不是推诿，是避免用错误的根因浪费一次发布窗口。**

## 3. 需要你提供的最小证据集（按价值排序，前 3 条最关键）

1. **浏览器 Console 首屏完整报错**（含堆栈首行）+ **Network 面板**：
   - `index.html` 的 HTTP 状态码
   - 主 JS/CSS 是否有 404 / 403 / 5xx / `(failed)`
   - 是否有 MIME 类型错误（如 `text/html` 返回了 JS）
2. **影响面**：全量用户白屏，还是仅部分用户 / 特定浏览器（尤其 iOS Safari 低版本）/ 特定入口 URL（直接访问子路径？刷新？）
3. **本次发布变更清单**：上线版本号、与上一版的 `git log --oneline A..B`、构建产物 hash 是否变化
4. **部署形态**：静态托管 / CDN / 容器 / SSR？是否开启 CDN 缓存、是否有灰度
5. **可观测性数据**：JS 错误率曲线、资源加载失败率、是否有 sourcemap 可关联到源码
6. **可复现环境**：能否给我一个复现 URL 或本地 `npm run build && preview` 的复现步骤

> 只要给我第 1 条，我基本就能把 6 个假设砍到 1–2 个。

## 4. 白屏根因假设排序（**假设，非事实**，按「刚上线即白屏」场景的先验概率）

| # | 假设 | 1 分钟验证动作 |
|---|---|---|
| H1 | **资源路径/基址错误**：`base`/`publicPath` 与部署目录不匹配，或 CDN 前缀缺失 → 主 bundle 404 | Network 看主 JS 是否 404，看 `index.html` 里 script src 的实际 URL |
| H2 | **CDN / 浏览器缓存了旧 index.html**，引用了已不存在的旧 hash 文件 | 无痕窗口 + 强刷（Ctrl+F5）对比；看 `index.html` 的 `cache-control` |
| H3 | **运行时异常中断渲染**（空值解引用、API 契约变更、依赖升级 breaking change） | Console 首条 error 的堆栈 + sourcemap 定位 |
| H4 | **环境变量/配置缺失**：新版本引入的配置项未在部署环境注入（如 API_BASE、密钥前缀） | 对比部署环境变量与 `.env.example`；看是否有 `undefined` 相关报错 |
| H5 | **产物不完整/上传中断**：dist 缺文件或 CDN 回源失败 | 对比构建产物清单与线上可访问资源列表 |
| H6 | 前端路由/子路径刷新、浏览器兼容缺 polyfill、CSP 拦截内联脚本 | 直击根路径对比子路径；换浏览器对比 |

## 6. 拿到证据后的执行计划

1. `debugging`：复现 → 取证 → 定位根因 → **最小修复**（不大范围重构）+ 补一个能捕获该缺陷的回归测试
2. `code-review`：对修复 diff 做双轴审查（Standards / Spec）
3. `verification`：
   - Build / Lint / Type Check / Test 的真实输出（无证据则判定未完成）
   - 发布检查项：产物完整性、缓存策略、环境变量注入、回滚预案
   - 观测项：上线后 JS 错误率是否回落、资源加载成功率是否恢复

## 7. 剩余风险清单（当前已知）

| 风险 | 说明 | 缓解 |
|---|---|---|
| 根因未定位，存在二次复发 | 在拿到 Console/Network 证据前，任何修复都是猜测 | 先补证据再改码 |
| 生产环境我无法直接访问 | 需要你提供复现环境或日志导出 | 明确证据索取清单（第 3 节） |
| 缓存/CDN 可能掩盖修复效果 | 修完仍白屏可能是缓存未失效 | 修复验证时强制刷新 + 校验响应头 |
| 缺少 sourcemap 会导致定位慢 | 若线上无 sourcemap，H3 类问题只能靠现象推断 | 确认 sourcemap 是否上传/是否仅本地保留 |
| 监控缺失 | 若无可观测性数据，下次同类问题仍靠用户反馈发现 | 事后补前端错误上报 + 资源加载失败告警 |
| 回滚本身有风险 | 若本次发布含数据库/接口变更，回滚可能引发前后端版本不兼容 | 回滚前确认本次发布是否含后端/数据变更 |
