## 3. 需求补全（事实 / 假设 / 建议 三分开）

### 事实（已核实，不是记忆推断）
- 微信支付当前主线是 **API v3**（商户文档 pay.weixin.qq.com/docs/merchant），新接入不走 v2。
- 支付产品按场景分 5 类：**JSAPI（微信内网页）/ 小程序支付 / App 支付 / H5（微信外浏览器）/ Native（扫码）**；另有**服务商（合作伙伴）模式**（pay.wechatpay.cn），其入参、子商户号与分账逻辑与直连商户不同。
- v3 的硬性要求：请求签名（商户私钥 SHA256-RSA）、应答与回调签名验签、回调通知需 AES-256-GCM 解密、平台证书需支持轮换。

### 假设（未确认前不作为实现依据）
- 你要的是「在 ASCOS 项目里集成微信支付收款」，而不是「给当前对话开通微信 AI 支付 / AI 专属卡」（后者是另一条路径，见待确认 0）。
- 直连普通商户模式，不是电商服务商 / 合单支付。
- 本期范围：下单 + 支付结果回调 + 主动查单；退款、关单、对账文件、分账后续再说。

### 建议（我的默认技术取向，可推翻）
- 用**官方服务端 SDK**，不手搓签名；商户私钥、APIv3 密钥只走环境变量 / 密钥管理，**不进仓库、不进对话**。
- 本地订单表带状态机 + `out_trade_no` 唯一幂等键；**以回调为准、查单兜底**，前端跳回页面不作为到账依据。
- 回调接口固定顺序：验签 → 解密 → 幂等判定 → 业务落库 → 返回 2xx；失败按微信重试策略处理。
- 先用沙箱 / 1 分钱真实验证，再放量。

## 6. 剩余风险清单（当前已知）
1. 场景 / 商户模式未定 → 接口选型错误，返工成本高（**阻断级**）。
2. 无公网 HTTPS 回调地址 → 无法联调，需内网穿透或先部署到测试环境。

6. 平台证书轮换未实现 → 到期后验签全量失败。
