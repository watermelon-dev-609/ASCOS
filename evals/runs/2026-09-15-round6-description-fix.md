## 1. 干预（本轮唯一改动）

只改 `SKILL.md` front-matter 的 `description`，改两处：

| 位置 | 改前 | 改后 |
|---|---|---|
| `Use when` | 用户要写码、改码、查 Bug、做技术选型或准备上线。 | 用户要写码、改码**（包括代码中的 UI 文案、配置等局部修改）**、查 Bug、做技术选型或准备上线。 |
| `Not for` | 纯文案润色、通用知识问答、排期与人员沟通等非软件交付任务。 | **与代码或软件配置无关的**纯文案润色、通用知识问答、排期与人员沟通等非软件交付任务。 |

**为什么是这两处、而且只有这两处：**

- `Use when` 加限定语，把「改代码里的 UI 文案」显式收进来 —— **只修 T01 的根因**。
- `Not for` 加「与代码或软件配置无关的」，把纯文案润色收窄成**真正与代码无关**的那部分。
  不加这个限定，前一处的新增会和既有的 Not for 打架，模型仍可能判掉。

**明确不做（防止修复蔓延）：**

- **不**碰 `code-review` / review 覆盖面 —— 那是 T08 的缺口，本轮 T08 是 1/3，维持 observe。
  T01 与 T08 依 Round 5 §5 **不合并处理**。
- **不**改任何能力规则；**不**给 `non-negotiables` 加反向边界。

## 2. 规则升级 A：交付物降级为 corroboration

Round 5 暴露的缺口：T01 run 2 的回答里**有一张「剩余风险清单」**，
而旧 rubric 的 Activation evidence 第 3 条正是「输出 ASCOS 特有交付物（…/ 剩余风险清单 /…）」——
**按交付物名字匹配会把它误判成激活**。裸模型也能随手写出风险表。

**从本轮起改用三段式**（同时写入 `evals/README.md`）：

```text
Activation evidence

Primary evidence —— 满足任一即可判 fire：
1. 明确声明已加载、正在遵循或正在使用 ASCOS / SKILL.md；
2. 明确进入 ASCOS capability Skill，或给出正向路由链；
3. 出现 requirements / architecture 等高度特异的 ASCOS 行为形态。

Supporting evidence —— 仅可佐证，不能单独判 fire：
- PRD / ADR / DoD / 剩余风险清单 / 验证清单等交付物；
- 一般性的风险分析、测试建议、工程清单。

Not activation evidence：
- 明确说明 ASCOS / Skill 不适用于当前请求；
- 明确说明未加载 Skill 或直接回答；
- 仅提及 Skill 名称来解释为什么不使用；
- 裸模型也可能自然生成的单个工程交付物或标题。
```

**这一条的追溯效果**：T01 run 2 写了「剩余风险清单」，但同时明确负向路由、未加载
→ Supporting 单独存在，Primary 全无 → **仍是 `not_fire`**。Round 5 的实际判法因此被追认为合规。

## 6. 必须写明的可比性警告

后果：**即使本轮 T11–T20 拿到 0/30，也不能全归因于「description 无害」** ——
rubric 变严本身就会减少被判成 fire 的次数。这是本轮安全结论的**已知弱点**。

补偿手段：

1. 新增 **`loaded` 字段**做 rubric 无关的二次校验。子会话自报是否加载了 `SKILL.md`，
   这是一次**行为**，不依赖任何输出形态判据。
2. 但 `loaded` **没有 Round 4 基线**（当时没记这个字段），所以 C 只能看**绝对数**，
   不能算 delta。判据 B 仍以 rubric 判定的误触发为准。

后续若要真正可比，应当用**同一版 rubric** 重跑一次基线。本轮不做，记为待办。
