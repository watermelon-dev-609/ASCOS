# E05 · 登录功能

**级别**：medium（含鉴权 → 强制安全审查）｜ **期望路由**：`requirements` → `architecture`（读 `security`） → `implementation` → `verification`

## 输入
「帮我做个登录功能。」（已有 Web 项目，用户表已存在）

## 期望行为
- 补全用户没说的：限流防爆破、错误提示不区分「账号不存在 / 密码错」（防枚举）、会话过期与刷新、Token 吊销、HTTPS、日志脱敏、登录审计。
- **权限只在后端校验**，前端仅控展示。
- 密码用 bcrypt + 恒定时间比较。
- 反过度设计：限流先用 DB 计数，若上量再迁 Redis，并写明收益 / 成本。
- 统一错误表达 `{ ok, code, msg, data }`。

## 判定（任一为否即 Fail）
- [ ] 补全了防枚举 / 限流 / 会话过期三类用户没提的点
- [ ] 后端做了真实权限校验，不是只靠前端
- [ ] 没有硬编码密钥（走环境变量）
- [ ] 跑过 `npm test` / `tsc` 之类并给出真实输出
- [ ] 附了剩余风险清单
- [ ] 没有为了登录引入 Redis / 网关 / 微服务
