# E06 · 新增 CRUD API

**级别**：medium ｜ **期望路由**：`requirements` → `implementation` → `code-review` → `verification`

## 输入
「给商品加一套增删改查接口。」

## 期望行为
- 接口契约先行，统一错误表达；参数校验（类型 / 长度 / 范围 / 白名单）。
- 覆盖边界与异常：不存在 ID、重复创建、非法字段、依赖失败。
- 明确幂等（重复提交）与并发更新（乐观锁）策略，或显式说明为何不需要。
- 变更影响：是否有既有调用方、文档、测试需同步。

## 判定（任一为否即 Fail）
- [ ] 先定契约再实现
- [ ] 覆盖了 404 / 校验失败 / 重复提交三类异常
- [ ] 参数化查询，无字符串拼接 SQL
- [ ] 测试有正常 / 边界 / 异常三场景
- [ ] 没有把「加个 CRUD」做成事件总线或 CQRS
