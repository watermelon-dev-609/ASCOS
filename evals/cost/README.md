# ASCOS Stage 2 · 成本批次（cost batch）

阶段 1 回答的是「会不会触发、会不会误触发」，已经冻结在 v1.2.2。
**这一批回答的是另一件事：ASCOS 到底贵在哪里，多花的钱值不值。**

> 核心原则：**先测清楚贵在哪里，再优化；不要凭感觉删规则。**

本目录只定义**批次本身**（选哪些用例、记哪些字段、质量指数怎么算）。
每一轮的**执行协议与结果**写在 `evals/runs/`，本文件不重复。

---

## 1. 两臂

| 臂 | variant | 含义 |
|---|---|---|
| A | `without_skill` | Codex 原生，会话里**没有** ASCOS |
| B | `with_skill` | Codex + ASCOS v1.2.2 |
| C | `with_skill_candidate` | v1.3 候选（阶段 2F 才启用，本批不用） |

**臂的隔离是本批最关键的一步，也是最容易做错的一步。**
阶段 1 已经付过一次学费：当时用「显式要求先读 SKILL.md」搭 with 臂，
而**强制加载等于替模型做了"要不要触发"这个决定**，抹掉的正是被测变量。

成本批次里对应的风险是：如果两臂的系统提示或可用工具不同，
测到的差异就不是 ASCOS 造成的。因此两臂**必须**满足：

- 同一个 Codex 版本、同一个模型、同一个 reasoning effort
- 同一个工作目录内容（同一份夹具副本）
- 唯一的区别是 **ASCOS 是否可被发现**

隔离手段：为每一臂准备独立的 `CODEX_HOME`（同一份 `auth.json`、
同一份 `config.toml`，B 臂额外在 `~/.codex/skills/` 下放 ASCOS 技能包）。
**不修改用户真实的 `~/.codex`**，跑完即删。

## 2. 字段契约

每条运行记录一个 JSON 对象，落在 `evals/cost/results/cost-records.jsonl`：

| 字段 | 类型 | 谁提供 |
|---|---|---|
| `input_tokens` / `output_tokens` / `total_tokens` | 非负数字 | CLI 用量统计 |
| `seconds` | 非负数字 | CLI 计时 |
| `tool_calls` | 非负整数 | 事件流里 `tool_use` 计数 |
| `skills_loaded` | 字符串数组 | 事件流里实际读到的 Skill |
| `references_loaded` | 字符串数组 | 事件流里实际读到的 reference |
| `defects` | `{bugs, missed_edges, security, unnecessary_changes}` | 人工判定 |
| `over_engineering` / `verified` / `tests_pass` | 布尔 | 人工判定 |
| `stages` | `[{stage, tokens}]` | 事件流（阶段 2C 归属分析用） |

**两条硬规矩**：

1. **测不到就留空，不填 0。** 报告里显示 `—`。填 0 会把"没测"伪装成"测得 0"。
2. **`skills_loaded` / `references_loaded` 从事件流观测，不让模型自报。**
   自报不可靠（阶段 1 已踩过：批量跑时 9 例全自报 `loaded_skill=yes`，
   实际是第一条请求加载后其余继承上下文）。观测真实的文件读取才作数。

## 3. 质量指数 QI（**执行前定死，之后不再改**）

QI 起始 100，按观测到的缺陷扣分：

| 扣分项 | 权重 |
|---|:--:|
| `security`（每个） | 25 |
| `bugs`（每个） | 15 |
| `missed_edges`（每个） | 10 |
| `unnecessary_changes`（每个） | 8 |
| `over_engineering` | 15 |
| `verified == false` | 20 |
| `tests_pass == false` | 20 |

扣到 0 为止。**为什么现在定死**：权重变了会重新基准化所有轮次，
使得跨轮比较失效——这就是阶段 1 里"改 rubric 会机械地压低计数"同一个教训。
所以权重是**常量**而不是命令行参数。

**QI 刻意不含 completion（任务是否完成）。**
完成与否单独报告：一次失败的运行不该被重复计两次（一次算 fail，一次算缺陷）。

安全权重最高（25）是刻意的价值判断：漏一个鉴权缺陷比多写两个文件严重得多。
这条是**主观的**，但正因为主观，更必须在看到数据之前写下来。

## 4. 本批 12 个用例

复用既有用例，不新建——既有用例已经带 `## 输入`、`判定`、`route`，
重写一遍只会制造两份会漂移的任务定义。分档见 `manifest.json`。

| 档 | 用例 | 对应你列的类型 |
|---|---|---|
| small 4 | E01 E02 E03 E04 | 按钮文案、改名、颜色、空状态 |
| medium 4 | E05 E06 E07 E08 | 登录、CRUD 接口、分页搜索、表单重复提交 |
| large 4 | E10 E11 E12 E13 | RAG、多租户、模块拆分、从零搭项目 |

**E09（接微信支付）被排除**，原因记录在案：本宿主存在微信支付连接器，
会把请求截走，属于**环境污染物**而非被测行为（阶段 1 的 T05 就是这个情况，
当时判定 `invalid` 并排除出分母）。把一个已知会被污染的用例放进成本批次，
只会得到一个无法解释的数字。

**E13 需要空目录**（从零搭项目），其余 11 例在 `eval-fixtures/cost-app` 的
**每例独立副本**中运行——同一份夹具被前一次运行改过，后面的运行就不再是同一道题。

## 5. 已知局限（先写下来，免得事后当成结论）

- **单模型**：本批只跑一个固定模型。换模型 QG/TC 会变，结论不外推。
- **缺陷由人工判定**：`defects` 与三个布尔字段不是自动得出的，判定标准
  写在每一轮的 `evals/runs/` 协议里，且必须在看到结果之前写死。
- **不测 token 单价**：只记 token 数与耗时，不折算金额（价格会变）。
- **`stages` 归属是近似**：按事件流中的阶段划分求和，不等于精确的上下文切片。
