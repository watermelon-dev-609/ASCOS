# 工程规范硬约束摘要

本文件是**跨技术栈的硬约束基线**；按技术面的细节见 `frontend.md` / `backend.md` / `database.md` / `security.md`。

## 设计原则
高内聚低耦合、单一职责（SRP）、KISS / DRY / YAGNI。

## 契约与错误表达
- 接口契约先行：先定义接口与数据结构，再实现。
- 统一错误表达（Web 后台示范）：`{ ok, code, msg, data }`，前后端共用同一套错误码；错误信息对前端友好，不泄露内部实现细节（详情只进服务端日志）。

## 业务与 IO 分离
业务逻辑不依赖具体存储 / 网络 / 文件实现；IO 隔离在独立一层，便于替换与测试。

## 安全（所有外部输入都是敌人）
- 所有外部输入（用户输入、接口参数、上传文件）一律校验并过滤非法字符。
- 参数化查询防注入；查询参数走**白名单**（拒绝操作符对象与含 `$` 的值）。
- 鉴权 + 授权：真实校验只在后端；**前端仅控制展示，绝不能作为安全边界**。
- 配置与密钥走环境变量，**禁止硬编码**；日志脱敏（口令、token、手机号、身份证不落日志）。
- 用户输入渲染前必须转义，禁止直接拼接 HTML。

## 可靠性
- 写操作（计分、状态流转、创建）必须**幂等**。
- 多步写操作要么全成功要么全回滚，不留半成品状态。
- 关键资源（积分、库存、状态变更）考虑并发，必要时加锁或条件更新。
- **先校验再改状态**，避免"校验失败但状态已改"。
- 连接、句柄、定时器、监听器用完即释放。

## 可观测
结构化日志、关联 ID、关键指标、依赖失败与超时监控（详见 `observability.md`）。

## 前端体验
- 四态齐全：loading / 空数据 / 报错 / 无权限。
- 表单提交前完整校验；按钮防抖或禁用防重复提交。
- 弹窗支持 ESC 与点击遮罩关闭；可交互元素有视觉标识（下拉箭头、列表项 `›`）。
- 破坏性操作不占"取消"的位置。

## 测试
核心逻辑与公共模块覆盖**正常 / 边界 / 异常**三类场景（详见 `testing.md`）。

## 技术栈适配（原则优先于模式）
`controller/service/repository`、SQL 优先、`{ ok, code, msg, data }` 是 **Web 后台的原则性示范**。
应用到 CLI、数据管道、ML、移动端、嵌入式等场景时：保留原则（契约先行、输入校验、业务/IO 分离、统一错误表达、可观测、测试三场景），**不必照搬具体模式**（如 CLI 可用退出码 + stderr 而非 HTTP 风格错误码），按实际栈适配。
