# 不可妥协规则（单一事实来源）— Single Source of Truth

本文件是以下三条规则的**唯一权威来源**。SKILL.md 与各个 reference 只**引用**本文件，不得另行复述原文，避免多份副本漂移（改一处要改五处）。

其他文件统一用「见 `references/non-negotiables.md` 第 N 条」的方式引用，不要复制文字。

---

## 第 1 条：禁止虚构完成度分数
不得以 `90/100`、`95% 完成`、`A+` 之类**虚构量化分数**作为「任务完成」的判定条件或交付结论。
完成与否只能由 DoD 清单（`skills/verification/SKILL.md` 第 2 节）逐项判定。可描述定性状态（如「核心路径已实现并自测通过，发布检查待补」），但不得用编造的数字伪装完成度。

## 第 2 条：交付必附风险清单
任何规模的交付，最后都必须附**「剩余风险清单」**，主动暴露未覆盖的薄弱处，至少覆盖：
- 越权 / 未授权访问
- 注入（SQL / 命令 / NoSQL）
- 并发竞态 / 幂等缺失
- 数据泄露 / 日志脱敏缺口
- 依赖与供应链风险
- 未验证项（含原因）

无风险清单不得声称交付完成。

## 第 3 条：输出自适应（按规模裁剪，不倾倒过程）
- 内部思考可完整使用全部角色视角；但**对外输出按任务规模裁剪**，不每次倾倒所有角色台词。
- **小任务**：结果 + 关键假设 + 风险。
- **中任务**：需求补全 + 实现 + 测试 + 风险与后续改进。
- **大任务**：需求补全 + 架构 / 设计 + 实现 + 测试 + 文档 + 风险。
- 仅在**重大问题**（安全漏洞、架构冲突、需求自相矛盾）时显式标注【安全视角】【架构视角】等，帮助聚焦；不强制每个任务输出内部角色过程。

### 裁剪的执行判据（补于 2026-09-14，22 例回归后）
回归里 4 个小任务用例**无一例外**输出过重（改一行文案给出 8 条风险 + 4 个问题 + 完整路由推演），
原因是第 2 条的 6 类风险被当成**输出模板**而非**检查清单**。据此明确：

1. **第 2 条的 6 类是检查清单，不是输出模板**。逐类过一遍，但**只写命中的**。
   在一行文案改动上写「注入 / 越权 / 竞态：本次不适用」= 把内部检查过程倾倒成对外输出。
2. **小任务的交付 = 改动点 + 复用说明 + 真正适用的风险（通常 ≤3 条）**。
3. 不输出路由判断过程（「我调用了哪些 Skill、为什么」），不重述 Skill 原文。
   用户要的是结果，不是我们的流程图。
4. **提问同理**：小任务最多问 1 个**真正阻断**的问题，其余按默认推进并标为假设。
   第 2 条要求附风险清单，不等于要求先问完再动手。
