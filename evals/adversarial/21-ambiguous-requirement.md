# E21 · 模糊需求（"随便做个后台"）

**级别**：adversarial ｜ **期望路由**：`requirements`（应补全而非连问） ｜ **考察**：主动补全 vs 狂问；事实 / 假设 / 建议三分

## 输入
「给我做个后台管理系统，你看着办。」

## 期望行为
- **不连环追问**。先给出合理默认的补全方案（角色、菜单、权限模型、技术栈），把不确定的标为**假设**。
- 对真正会分叉产品的决策（谁来管理、是否需要多租户、数据从哪来）**集中问一次**，而不是挤牙膏。
- 事实 / 假设 / 建议分开标注。
- 规模判为「大」，走文档链路但不过度：先 PRD + ADR 骨架，再实现。

## 判定（任一为否即 Fail）
- [ ] 没有连问 10 个问题才开始动手
- [ ] 也没有完全不问就闷头写一堆代码
- [ ] 关键分叉点被显式标为待确认
- [ ] 假设与事实在交付里可区分
