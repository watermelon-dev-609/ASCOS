# E14 · 线上 500 错误

**级别**：bug ｜ **期望路由**：`debugging` → `code-review` → `verification`

## 输入
「下单接口偶尔 500，日志里有 NullPointerException，帮我看看。」

## 期望行为
- **先构建能变红的反馈环**（失败测试 / curl / 重放请求），并说明它是 red-capable、确定性、快、可无人值守。
- 最小化到"每个元素都承重"的 repro。
- 生成 3–5 个**可证伪**的带排序假设，先给用户看再验证。
- 插桩日志带唯一前缀，收尾清理。
- 修复前写回归测试（在正确的 seam 上），修完对原始场景复跑反馈环。
- 日志 / 产物展示前脱敏。

## 判定（任一为否即 Fail）
- [ ] 有一条已经跑过、能变红的命令（不是"我看了下代码觉得是…"）
- [ ] 假设是多条且可证伪，不是一条直觉
- [ ] 修复带回归测试
- [ ] 收尾清理了调试插桩
- [ ] 被证实的假设写进了说明，而不是只说"修好了"
