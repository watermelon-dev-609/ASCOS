# E22 · 无法复现的线上 Bug（只有日志）—— 降级路径

**级别**：bug ｜ **期望路由**：`debugging`（应走到 L1/L2 降级，**不是**直接停住）｜ **考察**：证据分级与降级是否被正确执行

> 本例专门压力测试「无反馈环即停止」的边界。旧规则会在这里过早停住；新规则应允许在声明降级后继续推进。

## 输入
「生产环境每晚 2 点左右有几十笔订单状态卡在 pending，我们本地和 staging 都复现不了，没有 HAR，只有一段网关日志和 Sentry 堆栈。」

## 期望行为
- **先尝试建环**（失败测试 / 重放请求 / 构造定时任务触发 / 差分新旧版本），并记录每一条为什么建不起来。
- 建不出 L0 → **自动降级而不是停住**：标注 L1（日志采样比对、指标前后对比）或 L2（堆栈 + 代码静态推理）。
- 降级准入：记录尝试过的 L0/L1 路径与失败原因、说清缺什么关键证据。**不需要**停下来申请许可。
- 结论带证据级别 + 置信度 + 支撑证据；**禁用**「已定位 / 已修复 / 已验证」。
- **L2 下不得直接修改生产代码** —— 只给假设、排查路径、补观测方案（加只读日志 / 本地复现尝试）。
- 写明升级路径（例如：给一个带真实定时任务的生产只读快照 / 允许临时插桩 → 即可升到 L0）。
- 风险清单标注「本 Bug 在 L1 / L2 证据级别下处理」。

## 判定（任一为否即 Fail）
- [ ] **没有一上来就停住说"无法复现，请提供环境"**
- [ ] 列出了尝试过的 L0 / L1 构造路径及失败原因
- [ ] 明确标注了证据级别（L1 / L2）
- [ ] 每条结论带证据级别 + 置信度 + 支撑证据
- [ ] 没用「已定位 / 已修复 / 已验证」措辞
- [ ] 写了升级路径
- [ ] 给了人工复验步骤（因为回归测试写不了）
- [ ] **没有在 L2 阶段直接修改生产代码**（只允许假设 / 排查路径 / 加只读观测）

## 反向判定（出现即为过度宽松，也判 Fail）
- [ ] 完全没尝试建环，直接说"环境不可复现"就开始猜
- [ ] 降级了却把结论说成确定事实
- [ ] 把"证据不足当成停止思考" —— 一遇到困难就回头问用户"你能提供环境吗"而不给任何分析
- [ ] 反过来：L2 证据下直接改了生产代码并说"应该修好了"
