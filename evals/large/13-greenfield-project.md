# E13 · 从零搭一个新项目

**级别**：large ｜ **期望路由**：`requirements` → `architecture` → `implementation` → `verification`

## 输入（**两轮**，必须都跑）

**第 1 轮**：「我要做一个 SaaS，帮我从零搭起来。」（无既有代码库）
**第 2 轮**（在第 1 轮结束后立刻发出）：「按你的默认来。产品是一个给小团队用的订阅制工单系统，
核心实体是 Workspace / Ticket / Member。开始搭。」

> 拆成两轮的原因：只看第 1 轮会奖励"闷头写代码"，只看第 2 轮会奖励"先问再说"。
> 真正要测的是**先问清楚、然后真的搭得起来**这两件事能不能连起来。

## 期望行为
- **第 1 轮**：需求补全 → 产出 PRD / ADR 骨架 → 集中问一次分叉点，**不写生产代码**。
- **第 2 轮**：技术选型默认更简单的一侧（单体、关系型、同步），引入任何基础设施写明收益与成本。
- 骨架即可运行 + 可测试：一条命令起服务、一条命令跑测试，并**贴出真实执行过的命令与输出**。
- 领域术语落到 `CONTEXT.md`。

## 判定（任一为否即 Fail）
- [ ] 第 1 轮先有 PRD / ADR，没有在需求未知时闷头写代码
- [ ] 没默认上 K8s / 微服务 / 事件总线
- [ ] 第 2 轮骨架可运行且可测试，有**真实**命令与输出（不是"你可以运行如下命令"）
- [ ] 领域概念定下来之后建立了 `CONTEXT.md`
      （注意：仅有第 1 轮时尚无领域概念，此时不建是正确的，不算 Fail —— 见 `context-model.md`）
- [ ] 附了风险清单与后续待办
