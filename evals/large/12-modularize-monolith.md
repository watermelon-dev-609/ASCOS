# E12 · 单体模块化重构

**级别**：large ｜ **期望路由**：`architecture` → `implementation` → `verification`

## 输入
「现在代码全糊在一起，帮我拆成清晰的模块。」

## 期望行为
- 先做代码库感知：现有依赖图、热点文件、既有约定（`repository-awareness`）。
- 用深模块判据决定边界：删除测试、接口即测试面、**一个 adapter 是假 seam，两个才是真 seam**。
- 优先**进程内模块边界**，不默认拆成微服务 / 引入 MQ（反过度设计）。
- 每个模块边界给 ADR（背景 / 决策 / 备选 / 后果）。
- 增量迁移，可随时停下，不留半成品状态。

## 判定（任一为否即 Fail）
- [ ] 边界决策有明确判据，不是按目录拍脑袋
- [ ] 默认进程内拆分，没有直接上微服务 / MQ
- [ ] 关键决策有 ADR
- [ ] 迁移可分步，不要求一次性大爆炸式切换
- [ ] 变更影响覆盖了所有调用方
