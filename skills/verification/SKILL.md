# Verification — 验证与门禁

代码写完 ≠ 任务完成。本 Skill 用**证据**判定能否放行，并产出必附的剩余风险清单。

## 契约
- **输入**：全部产物（代码、测试、文档）+ `implementation` / `debugging` 给出的验证命令
- **输出**：**完成状态**（三态之一）+ DoD 逐项结论 + 质量门禁结论 + **剩余风险清单** + 未验证项说明
- **失败状态**：核心路径拿不到真实验证证据 → 状态判为 **Incomplete**，禁止声称"已通过 / 已修复"；
  未验证项不在核心路径时可判 **Complete with accepted risk**，但必须写明"在 X 未验证的前提下交付"

## 1. 完成前验证（取证据）
- 能运行时：执行 Build / Test / Lint / Type Check，用真实结果说话。
- 关键路径必须实际验证，不能口头判断"应该没问题"。
- 把**命令 + 结论**写进交付说明。
- 验证失败即回到修复，不强行交付。

### 非代码任务的验证（设计 / PRD / 架构类产物）
产物是文档或决策时，证据改为：
- **需求补全闭环**：列出「用户原话 → 我们补全了什么 → 是否仍有待确认项」。
- **决策可追溯**：每个关键选型能在 ADR 中查到依据与备选。
- **一致性检查**：PRD → ADR → API_SPEC → TEST_PLAN 链路无矛盾（见 `references/artifact-continuity.md`）。
- **对抗性反问**：能否举出一个该方案会失败 / 被滥用的具体场景？举不出说明没想透。

无上述证据时，不声称「方案已完备」，并显式标注未验证项。

## 2. 完成定义（DoD）— 三态判定，不是二值勾选

**先定状态，再逐项打勾。** 状态只有三种：

| 状态 | 判定条件 | 能否说"完成" |
|---|---|---|
| **Complete** | 下列 7 项**全部**满足 | 可以 |
| **Complete with accepted risk** | 除第 2 项外全部满足；第 2 项以「明确未验证说明」结清，且**未验证范围不在核心路径**上 | 可以，但必须写明"在 X 未验证的前提下交付" |
| **Incomplete** | 核心路径（Build / Test）无证据，或任一阻断项未过 | **不可以**，禁止声称完成 |

> 旧版本把「Build/Test 通过，**或有明确未验证说明**」塞进同一条勾选项，
> 与"全部满足才算完成"自相矛盾 —— 结果是"核心路径没跑但解释了原因"也能被勾成完成。
> **未验证 ≠ 未完成，但未验证核心路径 = 未完成。**

- [ ] 1. 实现完成（需求与补全项均已落地）
- [ ] 2. 验证完成（Build / Test / Lint / Type Check **通过**）—— 没跑就在本项写明未验证范围与原因，并按上表**降级状态**
- [ ] 3. 关键测试通过（正常 / 边界 / 异常；安全权限相关含攻击路径）
- [ ] 4. Code Review 完成（见 `code-review`）
- [ ] 5. 安全与权限检查完成（鉴权 / 授权 / 注入 / XSS / 越权 / 脱敏）
- [ ] 6. 风险清单已输出（见 `references/non-negotiables.md` 第 2 条）
- [ ] 7. 必要文档同步更新（PRD / ADR / API_SPEC / TEST_PLAN 按需）

## 3. 质量门禁（阻断严重缺陷，非严重记为风险）
- [ ] 安全：鉴权 / 授权 / 注入 / XSS / 越权 / 脱敏 已检查
- [ ] 输入：所有外部输入已校验
- [ ] 契约：接口与错误码符合统一规范
- [ ] 可靠性：幂等 / 事务 / 竞态已处理（如适用）
- [ ] 测试：正常 / 边界 / 异常覆盖，关键路径通过
- [ ] 资源：前端资源释放、后端连接 / 句柄释放
- [ ] 配置：无硬编码密钥，敏感项走环境变量
- [ ] 文档：关键逻辑有注释，变更有说明

**出现任一 → 阻断**：未鉴权的敏感操作、SQL 注入风险、硬编码密钥、无测试的核心逻辑、越权风险。
不因非严重瑕疵无限迭代；非严重问题记为风险。

## 4. CTO 最终检查
目标是否达成（用户真实意图，而非字面请求）？有重大需求缺失吗？架构是否适度（无过度设计）？安全模型成立吗？测试覆盖的是有意义的行为吗？部署 / 运维可行吗？

## 5. 发布 / 迁移 / 回滚检查（仅涉及上线时）
见 `references/release.md`：迁移可回滚、向后兼容、部署顺序、灰度策略、回滚或 Forward Fix 方案、上线后健康检查。可观测性见 `references/observability.md`。

## 6. 交付输出
- 产物（代码 / 文档 / 链接）
- 关键决策简述（为何这样选）
- **剩余风险清单**（必附）：覆盖哪些类别见 `references/non-negotiables.md` 第 2 条
  （唯一事实来源，**本文件不复制其清单**，避免两处漂移）
- 输出按规模裁剪，见 `references/non-negotiables.md` 第 3 条
- 明确标注本次交付属于上表哪种**状态**（Complete / Complete with accepted risk / Incomplete）

## 反模式
- 用虚构分数（90/100）作为完成条件（第 1 条禁令）。
- 没跑命令就说"测试通过"。
- 因非严重瑕疵阻断交付而不记风险。
- 本地开发强行套用发布检查。
