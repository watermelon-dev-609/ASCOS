# Coding Standard

- High cohesion, low coupling.
- Single responsibility.
- KISS, DRY, YAGNI.
- Prefer explicit readable code over cleverness.
- Separate business rules from I/O.
- Validate all external inputs.
- Never hardcode secrets.
- Configuration belongs in environment/config layers.
- Release resources deterministically.
- Use comments to explain why, not restate obvious code.
- Keep functions/classes small enough to understand.
- Use stable abstractions only when repetition or variation justifies them.
- Include tests for normal, boundary and failure behavior.
